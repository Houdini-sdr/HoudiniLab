| P2 | AP-10 | **Live viewing mode is blind to RX gaps, and two TX failure paths are unreported.** Reported symptom [user]: constellation smearing and phase jumps on the LIVE viewer while recorded captures of the same link look clean. Code review of the RX call path found the asymmetry is real and expected. **(1) Gap blindness (primary).** `Radio::recvHoudini` detects a lost-packet gap, zero-pads it so the rest of the window keeps true timing, and pushes the extent to the process-wide `RxGapSink` (`Radio.cc:255-273`). The ONLY consumer is the HDF5 finalize (`recorder_worker.cc:654`); view mode branches away from HDF5 (`:391`, `:687`), so nothing drains or consults the sink. `rx_gap_sink.h:40-42` documents this ('view mode detects+pushes gaps but never drains') but only to cap memory, not to inform the estimate. `sendCsi` therefore FFTs the padded slot with no indication part of it is zeros, and the resulting H is CACHED per antenna (`csi_h_`) and reused to equalize every following U slot until the next pilot, so ONE lost packet smears a burst of frames rather than one. The recorded file is not cleaner; it just carries `/Data/Gaps` so offline analysis can find the damage. **(2) U-slot TX return discarded** (`receiver.cc:781-783`): the uplink-data burst the constellation is built from ignores its `radioTx` return, while the pilot burst one block above checks it and warns. **(3) Async TX status never polled**: `readStreamStatus` is called nowhere (only commented out at `BaseRadioSetUHD.cc:298`), so a burst accepted but sent LATE, or dropped for lateness, is silent. On the `tdd=1` 3.125 us grid a late pilot is exactly a phase-jump mechanism. **Also found, lower severity: (4)** gap detection is conditional on `SOAPY_SDR_HAS_TIME` (`Radio.cc:255`), so a read returning without it is spliced with no check and no pad, the exact corruption the Tier-2 fix exists to prevent (whether the driver always sets it is a driver question, unverified from here); **(5)** a gap larger than the window remainder truncates real data silently (`Radio.cc:257,262`: `pad` clamped to the remainder, then `keep=min(r, remainder-pad)`, so the just-read samples are dropped unlogged). **APP-SIDE FIX BUILT** (`feat/correlator-testing`): gap state now rides the packet instead of a side channel only the file writer reads. `Radio::lastPadSamples()` reports the zeros inserted into the last window; `houdiniTddRx` latches it once per frame (that path serves every rx slot from ONE continuous read, so it applies to P and U alike); `Packet` carries `rx_pad` (safe: all strides are `sizeof(Packet)`-derived, no file format includes the header, and `data[]` moving 16->20 breaks no aligned SIMD load -- `symbolFft` is scalar, the correlator uses unaligned loads, muFFT's aligned kernels use their own buffers); `streamCsi` refuses a padded slot and warns <=1/5 s, so the display holds its last good estimate instead of rendering a false one. Recording mode deliberately unchanged (it keeps the samples because it writes the extents). U-slot TX return now checked in `clientTxPilots`. Build clean, no new warnings, `Packet` layout verified directly. **FOLLOW-UP FIX (same branch) closes the residuals, plus a bigger one they led to.** **Short reads were not propagating** -- and with `rx_gap_break` ON (the driver DEFAULT, verified three ways: `GetKwargBool(args,"rx_gap_break",true)`, `bool rx_gap_break = true`, and advertised `info["rx_gap_break"]="1"`), a SHORT read is precisely how a dropped packet surfaces, so this was the normal loss path. Two holes: (a) `loopRecv` declared `long long frameTime;` UNINITIALIZED and failed only on a NEGATIVE return, while `houdiniTddRx` returns 0 without touching `buffs`/`frameTime` -- so a 0-return built a Packet with garbage frame/slot ids over stale samples (undefined behavior); now initialized, and a 0-return frees the reserved buffers and continues. (b) A partially short read was accepted silently: `align_slot()` clamps a slot start to `cg`, so slots past the received data were extracted from the tail and looked valid; the shortfall now folds into the frame's untrusted count so the view path refuses them. **(3) CLOSED:** async TX status now drained (`Radio::drainTxStatus` -> `ClientRadioSet` -> `clientTxPilots`, once per horizon); the driver merges device-side late/off-grid drop events for live TX streams, so a late burst on the 3.125 us grid is now logged instead of appearing only as a phase jump. **(4) CLOSED:** an unstamped RX read now warns instead of splicing silently, and `rx_gap_break=1` is requested EXPLICITLY on both BS and UE RX streams -- a behavioral no-op against the default, but it stops our gap accounting depending silently on a default another repo owns (`recvHoudini` only compares timestamps BETWEEN reads, so an intra-buffer splice would be invisible to us; that contract is what rules it out). **(5) WITHDRAWN -- the original finding was WRONG:** `readStream` is called with `samples - got`, so `r` can never exceed the window remainder, and the truncated tail lies beyond the window boundary, which a fixed-size window discards regardless. Also fixed a bug this work introduced and the build caught: `MLPD_WARN` is a multi-statement macro, so unbraced guards gated only the header and would have printed the body every burst. NOT yet reproduced on silicon (boards in use at review time) and NOT a single-run observation: these are code-path findings. Verification plan: record over the same link and compare `/Data/Gaps` rate against the observed smear rate. Detail: `CC/Sounder/CSI_DEMO_WALKTHROUGH.md` section 8.3. | app fix built, UNVALIDATED on silicon |
